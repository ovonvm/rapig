# 2. 环境与依赖

Rapig 的设计目标是「一台低配机器、一个程序文件」。除了可选的反向代理和 qBittorrent，不需要安装其它运行时。

## 2.1 运行条件

| 项目 | 要求 |
|---|---|
| 操作系统 | Linux x86_64（推荐 systemd）；Windows 10/11 x64；其它系统可用源码自行构建 |
| 内存 | 建议 512 MB 以上（默认 low 配置在 300 MB 量级即可运行） |
| 磁盘 | 按文件量准备；数据库和文件都在数据目录下 |
| 浏览器 | Chrome/Edge/Firefox/Safari 的近两年版本；移动端浏览器可用 |
| 端口 | 默认 `127.0.0.1:50011`，可通过配置修改 |
| 权限 | Linux：安装与 systemd 操作需要 root，程序本身以普通用户运行；Windows：控制面板需要管理员权限 |

## 2.2 不需要什么

- 不需要 Node.js、Go、Python 或 .NET 运行时（Windows 控制面板是自包含单文件）。
- 不需要 MySQL/PostgreSQL/Redis：数据库是程序内的 SQLite，单文件存放。
- 不需要 ffmpeg：Rapig 不做服务端转码，能否播放由浏览器决定。
- 不需要对象存储或共享盘：文件保存在本地目录。

## 2.3 可选组件

| 组件 | 用途 | 说明 |
|---|---|---|
| qBittorrent 4.6+ / 5.x | 磁力链接与 `.torrent` 种子的离线下载 | 需要开启 WebUI，并把地址/用户名/密码配置给 Rapig |
| Nginx / Caddy | 反向代理、HTTPS、域名访问 | 见「5. 反向代理与 HTTPS」 |
| rsync + sqlite3 或 python3 | 备份脚本 `scripts/backup.sh` | 缺少时脚本会提示安装；也可停服后手工拷贝 |
| 证书文件 | HTTPS | 由反向代理提供，Rapig 本身不直接管证书 |

## 2.4 平台差异

| 项目 | Linux | Windows |
|---|---|---|
| 安装 | `install.sh` 自动安装为服务 | 单文件 `Rapig.exe` 控制面板，双击即用 |
| 后台运行 | systemd 服务 `rapig` | 控制面板内启动核心进程；关闭窗口会停止服务 |
| 日志 | `journalctl -u rapig` | 控制面板首页运行日志；命令行方式会写日志文件 |
| 开机自启 | `systemctl enable rapig` | 控制面板「高级 → 登录 Windows 时自动启动」 |
| 升级 | `sudo rapig upgrade --binary <新程序>` | 停止服务后用新 `Rapig.exe` 覆盖旧文件 |
| 数据目录 | `/opt/rapig/data` | `%ProgramData%\Rapig\data` |

## 2.5 网络与端口

默认只监听本机回环地址，意味着只有这台机器上的浏览器能打开。常见选择：

- **只在本机用**：保持默认，不需要改任何配置。
- **局域网访问**：把监听地址改为 `0.0.0.0:50011`（或反向代理到本机），并确保防火墙放行；此时建议至少开启 HTTPS 或限制在可信网络。
- **公网访问**：请在反向代理上终止 TLS，并阅读「5. 反向代理与 HTTPS」的安全清单；不要把 Rapig 的明文端口直接暴露到公网。

## 2.6 从源码构建（可选）

普通用户不需要这一步。仓库自带构建脚本：

```bash
./scripts/build.sh        # 前端 + Go 核心，生成 Linux 发布包
./scripts/build-gui.sh    # Windows 控制面板（需要 .NET 8 SDK）
```

需要 Go 1.24+、Node.js 20+ 与 pnpm。构建细节见仓库根目录 `README.md`。

## 2.7 账号与权限前提

- Linux 安装方式会创建一个不能登录的 `rapig` 用户，数据目录归它所有；手工拷贝数据后如果权限不对，会表现为「能启动但打不开文件」或启动报错，修复方式是 `sudo chown -R rapig:rapig /opt/rapig/data`。
- Windows 控制面板以管理员身份运行，数据写在 `%ProgramData%\Rapig`；同一台机器的其它标准用户可能无权访问该目录。
