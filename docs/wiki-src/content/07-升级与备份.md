# 7. 升级、备份与迁移

网盘最重要的两件事：能升级，且升级前有备份、升级失败能退回去。本章覆盖这三件事，以及换机器时怎么把数据搬走。

## 7.1 升级前检查清单

- [ ] 已做一次完整备份（见 7.3），并确认备份文件存在、大小正常。
- [ ] 记录当前版本：`rapig version`。
- [ ] 阅读新版本的发布说明；如有数据库迁移，确认自己有回退路径。
- [ ] 选择低峰时间：升级期间服务会短暂停止。

## 7.2 升级

### Linux（推荐方式）

```bash
sudo ./scripts/backup.sh
sudo rapig upgrade --binary ./rapig-v2.0.1 --prefix /opt/rapig --port 50011
```

流程：停止服务 → 备份当前二进制 → 替换 → 启动 → 等待健康检查；失败会自动换回旧二进制并报错。旧二进制保留为 `rapig.bak-<时间戳>`。

源码仓库里另有 `scripts/upgrade.sh <新二进制>`，会先调用 `backup.sh`、原子替换并验证健康检查，失败回滚；它不在安装包内，安装包用户直接用 `rapig upgrade` 即可。

升级只替换程序，不会动 `rapig.env`、`data/` 和 systemd unit；数据库迁移在启动时自动执行。

### Windows

1. 控制面板「停止服务」。
2. 用新的 `Rapig.exe` 覆盖旧文件（先备份数据，见 7.3）。
3. 双击打开，点「启动服务」，确认能正常登录。

数据在 `%ProgramData%\Rapig`，覆盖 exe 不影响数据。

### 便携方式

停止进程，替换二进制，重新 `./rapig serve` 即可。

## 7.3 备份

### 备份什么

| 内容 | 位置（Linux 安装包） | 是否必须 |
|---|---|---|
| 数据库 | `<prefix>/data/db/rapig.db`（含 `-wal`/`-shm` 一起拷） | 必须 |
| 文件内容 | `<prefix>/data/storage/` | 必须 |
| 初始管理员信息 | `<prefix>/data/bootstrap/` | 可选 |
| 配置 | `<prefix>/rapig.env` | 建议 |

只备份数据库会丢文件内容；只备份 `storage/` 会丢索引，两者必须成对。

### 备份脚本（Linux）

```bash
sudo /opt/rapig/scripts/backup.sh
```

- 输出目录：`/opt/rapig/backup/<UTC 时间戳>/`，内部包含 `db/`、`storage/`、`bootstrap/` 和 `manifest.json`。
- 保留策略：最近 7 个 + 最近 4 个周日 + 最近 3 个每月 1 号。
- 依赖 `rsync` 和 `sqlite3`（或 `python3`），数据库用 SQLite 的在线备份接口做一致性快照。

用 cron 每天自动备份：

```cron
30 2 * * * /opt/rapig/scripts/backup.sh >> /var/log/rapig-backup.log 2>&1
```

### 备份脚本（Windows）

控制面板「高级 → 备份数据（zip）」会把整个数据目录打成 zip，放到 `%ProgramData%\Rapig\backups`。建议把该目录再同步到另一块磁盘或网络位置。

## 7.4 恢复

### 演练（不动真实数据）

```bash
sudo /opt/rapig/scripts/restore.sh --list                  # 列出快照
sudo /opt/rapig/scripts/restore.sh --snapshot <时间戳> --drill
```

演练会把快照解到临时目录并校验，不会覆盖正在运行的数据；建议每次备份后抽一次演练。

### 正式恢复

```bash
sudo rapig service stop
sudo /opt/rapig/scripts/restore.sh --snapshot <时间戳> --apply --yes
sudo rapig service start
```

恢复会覆盖数据目录，务必确认快照时间戳。Windows 恢复：停止服务 → 解压备份 zip → 用其中内容替换 `%ProgramData%\Rapig\data` → 启动服务。

## 7.5 迁移数据目录 / 换机器

**Linux**：停止服务 → 用 `rsync -a` 复制 `data/` 到新位置 → 修改 `RAPIG_DATA_DIR`（或 `rapig config`）→ 启动 → `rapig doctor` 复核。注意属主要改成运行用户。

**Windows**：控制面板「高级 → 更改数据目录」，只能选择空目录；程序会停止服务、复制数据、保存配置并重启。

**换机器**：在新机器安装同版本 → 停止服务 → 用备份恢复数据目录 → 启动并验证登录、文件列表、下载。域名与反向代理配置需要在新机器上重建。

## 7.6 回滚

- 程序回滚：把 `rapig.bak-<时间戳>` 改回 `rapig` 并重启；或重新安装旧版本二进制。
- 数据回滚：用升级前的备份快照做 7.4 的正式恢复。
- 若升级失败并自动回滚，检查 `journalctl -u rapig -n 100` 的报错后再决定是否重试。

## 7.7 常见问题

| 现象 | 处理 |
|---|---|
| 备份时报缺少 sqlite3/python3 | 安装其一，或停止服务后手工拷贝 `db/` 与 `storage/` |
| 恢复后文件在、但列表为空 | 数据目录指错了；检查 `RAPIG_DATA_DIR` 与运行用户权限 |
| 升级后无法启动 | 看日志；多数是 `rapig.env` 语法错误、端口占用或数据目录权限 |
| 磁盘快速变满 | 回收站与分享仍在占用空间；清理回收站/撤销分享，并确认备份目录不和数据同盘 |
